Sprint Documentation

This sprint focused on the core logic of connecting a patient's biological identity with their medical regimen.

●
Integrated Data Model: Developed a schema linking Biometric Logs (Pulse, Temp) and Prescription Schedules (Dosage, Frequency, Timing) to a single Patient ID.
●
Medication Logic Flow: Documented backend logic for "Adherence Windows"—calculating when a medication is "Due," "Taken," or "Missed."
●
Vitals Threshold Mapping: Defined "Safe Zones" for patient vitals; if data falls outside these ranges, the API triggers an alert.
●
Initial Endpoint Mapping: Defined structure for GET /patient/medications and POST /vitals/log.

Patch Notes — v0.1.0

ADDED Patient Vital Tracking

Dynamic ingestion for heart rate and body temperature. API validates numeric data within human-possible range (rejects HR of 0 or 500) before saving.

ADDED Daily Medication Scheduler

CRUD operations for patient medication lists. System automatically calculates next expected dose time based on initial entry and frequency.

ADDED Missed Dose Flagging System

If a "Taken" confirmation is not received within a 2-hour adherence window, system updates status from Pending to Late.

ADDED Security & Privacy (RLS)

Row-Level Security in the database ensures Medical Providers can only view vitals/medications of their assigned patients.
